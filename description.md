# Задание 2. Основные и связанные таблицы

## 1. Закупки продукции

Основная таблица: **bm_StorageOperations** (складские операции)

- ID: номер операции, например 4780421
- DocumentID: номер документа, например 388235
- OperationID: тип операции, например 1
- ProductID: номер товара, например 4368
- VendorID: номер поставщика, например 200
- ContractID: номер договора, например 0
- StorageID: номер склада, например 41

Связанные таблицы:

**bm_JournalBarnetDocs** (документы операций)

- ID: номер документа, например 1216
- ShiftID: номер смены, например 65
- DocumentTypeID: тип документа, например 1

**bm_StorageOperations_Table** (складские операции)

- ID: номер операции, например 134198
- DocumentID: номер документа, например 388540
- OperationID: тип операции, например 2
- StorageID: номер склада, например 41
- ProductID: номер товара, например 4345

**product** (справочник товаров)

- id: номер товара, например 4337
- productid: код товара, например 1204073
- description: название товара, например Бананы
- vendorid: номер поставщика, например 107
- flaging: флаг состояния товара, например 1

**vendors** (справочник поставщиков)

- id: номер поставщика, например 90
- clientid: название поставщика, например Габур
- clientgroup: группа поставщика, например 32
- serialnumber: серийный номер, например 0
- firstname: наименование поставщика, например ИП Габур

**bm_JournalTypeDocuments** (типы документов)

- ID: номер типа документа, например 1
- Description: название типа, например Ввод состава нового рецепта
- JournalID: номер журнала, например 1
- IsParent: признак родительского типа, например 0

**bm_Contracts** (договоры)

- ID: номер договора, данных нет
- ParentType: тип родительского объекта, данных нет
- CompanyID: номер организации, данных нет
- VendorID: номер поставщика, данных нет

**storages** (склады)

- id: номер склада, например 41
- CompanyID: номер организации, например 6
- description: название склада, например Склад
- CityID: номер города, например NULL

**bm_StorageOperationsType** (типы складских операций)

- ID: номер типа операции, например 1
- Description: название операции, например Поступление
- Factor: коэффициент операции, например 1
- DateAdd: дата добавления, например 2013-01-15 15:19:12.517

Связи, для которых в базе есть внешние ключи:

- bm_StorageOperations.DocumentID ссылается на bm_JournalBarnetDocs.ID, то есть операция связана с документом
- bm_StorageOperations.OperationID соответствует bm_StorageOperationsType.ID, то есть операция связана со своим типом
- bm_StorageOperations.StorageID соответствует storages.id, то есть операция связана со складом
- bm_StorageOperations.ProductID соответствует product.id, то есть операция связана с товаром
- bm_StorageOperations_Table.DocumentID, OperationID, StorageID и ProductID соответствуют bm_JournalBarnetDocs.ID, bm_StorageOperationsType.ID, storages.id и product.id
- bm_JournalBarnetDocs.DocumentTypeID соответствует bm_JournalTypeDocuments.ID, то есть документ связан со своим типом

Связь без внешнего ключа в базе:

- bm_StorageOperations.ContractID может соответствовать bm_Contracts.ID, но в операциях там стоит 0, а таблица договоров пустая

## 2. Продажи товаров

Основная таблица: **product** (справочник товаров)

- id: номер товара, например 4337
- productid: код товара, например 1204073
- description: название товара, например Бананы

Связанные таблицы:

**pricelist** (цены)

- id: номер записи, например 113681
- DocumentID: номер документа, например 142417

**vw_SalesTicketInfo** (продажи товаров и блюд, таблица фактов продаж)

- ID: номер записи, например 1675807
- TicketNumber: номер чека, например 10329777
- TicketDate: дата продажи, например 2020-11-11 23:27:34.000
- ProductType: тип продукции, например Блюдо
- BludoID: номер блюда, например 4520

Связи:

- pricelist.productid соответствует product.id, то есть цена относится к конкретному товару
- pricelist.DocumentID соответствует bm_JournalBarnetDocs.ID, то есть цена оформлена документом
- vw_SalesTicketInfo хранит фактические продажи по чекам: номер, дату и проданную позицию

## 3. Поставщики

Основная таблица: **vendors** (справочник поставщиков)

- id: номер поставщика, например 90
- clientid: название поставщика, например Габур
- clientgroup: группа поставщика, например 32

Связанные таблицы:

**bm_StorageOperations** (складские операции)

- ID: номер операции, например 4780421
- DocumentID: номер документа, например 388235
- OperationID: тип операции, например 1
- VendorID: номер поставщика, например 200

**bm_JournalBarnetDocs** (документы операций)

- ID: номер документа, например 1216
- JournalID: номер журнала, например 1
- ShiftID: номер смены, например 65
- DocumentNumber: номер документа в журнале, например 1
- Period: дата документа, например 2013-07-23 10:00:00.000

Связи:

- bm_StorageOperations.DocumentID соответствует bm_JournalBarnetDocs.ID, то есть операция связана с документом (внешний ключ есть в базе)
- bm_StorageOperations.VendorID соответствует vendors.id, то есть операция связана с поставщиком (внешнего ключа в базе нет, связь по смыслу)

Данные для точного расчёта задолженности перед поставщиками пока не нашёл.

## 4. Персонал

Основная таблица: **personnel** (сотрудники)

- personid: номер сотрудника, например 897
- firstname: имя, например Администратор Barnet
- lastname: фамилия, пусто

Связанные таблицы:

**bm_BonusHistory** (история бонусов)

- ID: номер записи, например 1
- ClientID: номер клиента, например 3352
- ActionName: название действия, например User
- PersonID: номер сотрудника, например 897

**bm_WorkHours** (рабочее время сотрудников)

- ID: номер записи, данных нет
- ShiftID: номер смены, данных нет
- PersonID: номер сотрудника, данных нет
- PersonName: имя сотрудника, данных нет

Связи:

- bm_BonusHistory.PersonID соответствует personnel.personid, то есть запись о бонусах связана с сотрудником (внешний ключ есть в базе)
- bm_WorkHours.PersonID, предположительно, относится к personnel.personid, внешнего ключа в базе нет, таблица пустая

## 5. Остатки

Основная таблица: **bm_StorageOperations_Table** (складские операции)

- ID: номер операции, например 134198
- DocumentID: номер документа, например 388540
- StorageID: номер склада, например 41

Связанные таблицы:

**bm_JournalBarnetDocs** (документы операций)

- ID: номер документа, например 1216
- ShiftID: номер смены, например 65
- DocumentTypeID: тип документа, например 1

**bm_Journal_Details** (детали журнала товаров)

- ID: номер записи, например 11530445
- SourceID: номер источника, например 1675591
- ProductID: номер товара, например 4407
- Quantity: количество, например 1.0000
- StorageID: номер склада, например 41

Связи:

- bm_StorageOperations_Table.DocumentID соответствует bm_JournalBarnetDocs.ID, то есть складская операция связана с документом
- bm_Journal_Details.ProductID соответствует product.id, то есть позиция журнала связана с товаром
- bm_Journal_Details содержит ProductID и Quantity, по ним видно товарные позиции и их количество
